# Responses API compatibility

This project provides a targeted OpenAI Responses API-compatible interface
on top of a ChatGPT Web browser execution backend.

It is not the official OpenAI API execution service.

## Verified

- `POST /v1/responses`
- Bearer authentication
- `model` request field
- `instructions`
- string and multi-message `input`
- user / assistant / system / developer roles
- `input_text`
- Base64/data-URL `input_image`
- non-stream Responses output
- SSE Responses lifecycle events
- function tools
- `tool_choice`: none / auto / required / specific function
- `parallel_tool_calls`
- strict function argument validation for the supported schema subset
- Responses `function_call` output items
- `function_call_output` input round trips
- standardized JSON errors
- official OpenAI Node SDK `responses.create()` compatibility tests

## Browser-backend limitations

- Requested model selection is not verified.
- Response model is reported as `chatgpt-web-unverified`.
- `usage` remains `null`; token usage is not fabricated.
- SSE text and function argument deltas are buffered because the browser
  execution layer currently exposes the final rendered response.
- Remote image URL execution is not enabled.
- Image `file_id` execution is not enabled.
- `input_file` is normalized but browser file execution is not enabled.
- Non-function tool execution is not enabled.
- The strict function schema validator intentionally supports a documented
  subset rather than claiming complete JSON Schema implementation.
- Arbitrary JSON generated by the model is never accepted as a function call
  unless it passes the nonce-delimited protocol parser and validation.

## Compatibility policy

Legacy `/demo/*` and `/browser/run` routes remain available.

New Responses compatibility work must not fabricate model identity, usage,
tool calls, or structured output that was not verified by the router.
